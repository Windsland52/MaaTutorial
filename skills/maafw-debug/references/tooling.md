# 取证手段与工具矩阵

配套 [SKILL.md](../SKILL.md) 各层检查动作的「怎么做」。分层：**诊断方法与硬要求在 SKILL.md，不随工具变**（像素空间一致、截图与点击走框架链路、判定分级）；**执行工具与命令契约在本文**——Agent 自主调试的默认执行工具定为 [maafw-live](https://github.com/Windsland52/maafw-live)，但不是所有调试场景的唯一依赖：人工在场走官方工具链、不要求为此安装 maafw-live，替代工具按能力逐项对应（见「替代工具能力对应」）。命令精确语法与参数以其仓库文档为准，本文只载选择判据、默认执行闭环与判定要点。

## 工作模式

| 模式 | 默认工具 | 适用与要点 |
| ---- | -------- | ---------- |
| Agent 自主 | 观测底座（[maafw-live](https://github.com/Windsland52/maafw-live)，作者维护） | 帧流常驻，人不必盯屏：`crop`（原始分辨率帧裁剪，识别空间一致）、`color`（探色）、`annotate`（候选区域编号选点）、关键帧库留存；命令细节以其仓库文档为准 |
| Agent 自主（无底座） | 自写脚本走框架截图链路 | 截图后程序化裁剪；同设备只走一条控制器链路，不与面板并发控制同一设备 |
| 人工在场 | 官方工具链：VSCode MSE / MFA 工具箱 / MPE | 交互式截图、裁剪、跑任务、看日志；课程主线是 MSE（Maa 控制面板 + Maa 日志 / 插件日志） |
| 事后离线 | MaaEvidenceKit（`maa-evidence`）/ MLA | 用户日志还原执行过程——超出本 skill 的开发态定位，交接 maa-evidence |

> 一句话定位：**maafw-live 是 Agent 自主调试的默认执行工具**（执行闭环见下节）；人工在场不需要它，已有等效工具按能力对应核过同样可用——环境与分辨率中立原则不变，判定标准仍是文末三条硬要求。

## 默认执行路径（maafw-live）

使用前置：读其仓库文档，并用它自带的探测命令确认版本与能力，不凭记忆——`version`（CLI 与依赖版本）、`env`（项目根、pipeline 目录、运行时绑定、外部工具；缺依赖是探测结果，不是错误）、`probe`（自检：绑定版本、设备发现数）。自动化调用照传 `--no-interactive` / `--no-color`——照传防后续版本引入交互提问或彩色输出挂住自动化调用，两标志当前行为以其文档为准。

调试闭环（各步命令与结果字段以其仓库文档为准）：

1. **复用或建立设备会话**：连接优先 `--project`（按 `interface.json` 的 controller 声明来，不猜设备）；多步操作走 `repl` / daemon——一个 daemon 子进程 = 一个设备会话，连接一次、命令复用。
2. **观测并留存现场**：`frame` / `screencap` 取帧（自动进 L0 缓存，有捕获身份可升格），关键现场 `kf promote` 升格进关键帧库——现场过了就取不回。
3. **单节点验证**：`reco` 识别单测（`--node` 整节点透传、`--param` / `--sweep` 阈值扫描——只识别不动作、无副作用；`--act` 识别拿框后真机执行动作半——有真实副作用，会改账号数据的动作前先确认）。`run` 以节点为 entry **不是**单节点验证：起跑后该节点的动作与 next / on_error 会继续执行（post_task 语义），调试一个点击节点可能把后续领取、提交一并跑了——隔离测试必须另行限制执行范围（如 `override` 同时置空该节点 `next` / `on_error`，把范围锁在本节点）；节点字段语义查 3.1 协议，命令与输出查其文档。
4. **动作前后核对**：输入注入（`click` 等）的动作边界帧自动入 L0 锚区，取前后帧逐像素核对落点与画面变化。
5. **局部流程复测**：`run` 跑任务（`override` 合成覆盖、`--timeout 0` 不自动停），验证改动在流程语境下生效。
6. **端到端验收**：分两档。**Pipeline 业务流程验收**——`run` 重复跑（含冷启动 / 重连）可承担，但结论须记录前置条件与 Agent 状态（本工具不执行 pretask、只警告；Agent 连接失败不阻断非 Custom 节点——`record.ok=true` 不证明这两项正常）；**目标 Client 集成验收**——实际经过目标 Client 的 pretask、资源 / 选项装配、Agent 启动与任务入口，工具跑通不能替代。两档都按下方判定要点分级判定——一次跑通 ≠ 稳定。

> **模式边界（run 与 Interface 选项合并）**：一次性 CLI `run --project` 会合成 Interface 的 pipeline_override 覆盖链（preset > default_case 取值，用户 `--override` 最后覆盖）；REPL 内的 `run` **不做这层合并**，只透传手工 `--override`。验证「Interface 选项有没有生效」走一次性 CLI 路径；在 REPL 里验证则显式合成 override 传入，并把所选 controller / resource / preset 与最终覆盖值留作证据——否则可能把「工具没应用选项」误诊成项目接线错误。

### 判定要点（maafw-live）

结果字段、JSON 信封与退出码全表以其仓库文档为唯一来源——使用前置已探测版本，勿凭记忆引用字段面。本节只固化下列不随工具版本变的判定纪律：

- **调用 ≠ 任务 ≠ 验收**：命令调用完成（进程退出 / 外层信封）不说明任务成功，任务级结果与实际识别结果按其文档另取；三层判定见 SKILL 硬护栏 5，互不顶替。判定链：CLI 信封 `ok` / `exitCode` → `data.ok` 与 `data.record` 是否存在（daemon 返回，区分「调用完成」与「任务已启动」）→ `data.record.ok`（任务级）→ 实际行为与期望（业务验收）。
- **外层 `ok` 不证明任务已启动**：CLI 信封 `ok` 按「退出码为 0 或 3」生成——`run` 根本没启动的调用级失败（未连接 / 资源缺失 / 已有任务在跑）正是退出 3，外层仍 `ok=true`。
- **run 的退出码 1 / 3 与字面直觉相反**：退出 3（FINDINGS）＝调用级失败，任务可能根本没跑起来（拿 `data.record` 是否存在确认）；退出 1（FAIL）＝任务已执行但任务级失败（`data.record.ok=false`）。其他命令语义不同（如 reco 未命中是 3、未预期异常才是 1），别跨命令套用。
- **REPL 的异步结果不是这套信封**：REPL 内 `run` 异步执行、完成时打印任务级摘要文本而非 CLI JSON，上述字段路径不适用，按会话内输出判读。

## 替代工具能力对应

不写笼统的「也可自写脚本」——替代工具（含自写脚本）按本次诊断需要的能力逐项对应，缺哪项就在定位结论里明说哪项无法验证：

| 能力 | 用途 | 缺失时 |
| ---- | ---- | ------ |
| 框架链路截图（可程序化取帧） | 当前帧取证、模板裁剪、前后帧对比 | 只能外部截图——违反像素空间一致，识别结论不作数 |
| 识别结果（命中 / 得分 / box） | 单节点验证、阈值与 ROI 调参 | 只知「过 / 没过」，无法归因 |
| 任务级执行状态 | 判定分级（SKILL 硬护栏 5） | 只剩退出码，任务失败与调用失败混同 |
| 框架日志（Maa 日志 / 插件日志） | 流程层按节点事件序列归因 | 卡死无法归因到节点 |
| 证据留存（帧 / 结果落盘） | 交接与复核（定位结论 + 证据） | 现场即弃，结论无法复核 |

人工在场（VSCode MSE / MFA 工具箱 / MPE）交互式覆盖截图、跑任务、看日志，是合法工作模式，不要求为此安装 maafw-live；短板是程序化复测与证据留存，验收记录靠人工整理。

## 配置层取证

| 检查 | 手段 | 硬要求 |
| ---- | ---- | ------ |
| 设备连通 | Android：`adb devices` 在列、USB 调试开启；桌面：窗口句柄 / 标题核对 | 设备可达 |
| 结构错误 | 有 dev-tools 的项目跑 `pnpm check`（schema + pipeline 静态检查） | 结构错清零再谈运行时 |
| 任务入口 / 资源 | 人工：MSE 面板读出任务与资源清单；agent：按 interface 声明核对 entry | entry 在合并后 pipeline 可解析 |
| 子进程状态 | 读 agent 自己的 stderr / stdout；Maa 日志 + 插件日志 | 双日志分开看 |
| 截图链路 | 框架截图 API / MSE 截图 | 分辨率与识别输入同空间 |

## 识别层取证

- **当前帧**：观测底座 `crop` / 自写脚本走框架截图链路 / 人工 MSE 截图——外部截图工具一律不用。
- **单节点验证**：默认 maafw-live `reco` 识别单测（`--act` 真机执行动作半，有副作用）；`run` 从 entry 起跑会继续执行 next / on_error、不是单节点验证（隔离用法见「默认执行路径」第 3 步）；节点字段语义查 3.1 协议，命令与输出查工具文档。输出命中 / 未命中、得分、box，与 hits/box 期望比对。
- **取色与色块**：观测底座 `color`。
- **候选区域选点**：无模板时 `annotate` 区域编号选点。
- **模板复核**：裁后自匹配——新模板在来源帧的来源位置应命中（位置优先于得分）。
- **不可复现状态**：从关键帧库留存帧裁剪，写前逐帧核对。
- **前后帧对比**：输入边界原图捕获（action-before / action-after 锚点，工具侧已落地；消费侧验收未做，仅作线索不作判定）。

## 动作层取证

- **落点比对**：观测底座框选 / MSE 交互截取，识别 box 与点击实际落点逐像素核对。
- **画面变没变**：点击前后帧对比（上节锚点或连续帧）——区分「画面已变点错」与「画面未变白点」两坑。
- **再识别确认**：单节点验证或观测底座连续帧。

## 流程层取证

- **卡死现场**：Maa 日志 / 插件日志按节点事件序列还原——当前节点、轮询列表逐项识别结果、timeout 计时（「最小取证序列」模板见 SKILL.md TODO）。
- **执行回放**：开发态看实时日志；用户反馈的日志还原属事后，转 maa-evidence / MLA。

## 验收层取证

- **判定**：任务级结果 + 实际识别结果，按 SKILL 硬护栏 5 分级（maafw-live 判定要点见上文）；具体字段与退出码随工具，一律按其仓库文档核对同层级信息。验收两档（Pipeline 业务流程 / 目标 Client 集成）的边界见「默认执行路径」第 6 步。
- **回归**：有 tests/ 基建（截图 + hits 期望约定）的项目补用例——静态识别回归，不证明动作 / 转移 / 端到端。
- **override 生效**：目标节点加临时可观察字段（改 action / 挂日志 Custom）验证落点。

## 工具替换判定

换工具只认三条硬要求，满足三条用什么工具是项目自由：

1. **像素空间一致**：模板、ROI、坐标必须与识别输入同源同空间；
2. **走框架截图链路**：截图与点击经框架（或与框架等价的控制器链路），分辨率一致；
3. **判定看任务级结果**：工具必须暴露任务级状态与识别结果（只有进程退出码的不够），判定以任务级 + 识别结果为准——分级见 SKILL 硬护栏 5，具体字段随工具（maafw-live 见「判定要点」）。
