# 反模式清单与审查清单

配套 [SKILL.md](../SKILL.md) 的审查要点展开。判定依据：MaaLLMWiki 路由的 `3.1-任务流水线协议`（版本锁定）。文中括号内的版本标注仅作提示，实际支持范围以路由结果为准。

## 坐标卫生细则

协议区分三个概念：`roi`（在哪识别）、`box`（识别命中返回的区域）、`target`（动作执行目标，默认 `true` 即继承当前识别 box，动作目标由 `target` + `target_offset` 共同决定）。

- **严禁 `DirectHit` + 硬编码 target**：绕过识别直接点绝对坐标，界面一变就点错。
- 点击目标默认继承本节点识别 box；OCR/Template 节点直接让点击落在识别结果上，需要偏移用 `target_offset` 并注明依据。
- 锚定偏移（引用之前执行过的节点的 box，string 形式写节点名，或 `[Anchor]锚点名` 引用）只在“目标相对参照物位置恒定”时可用，并注释前提；引用的节点/锚点识别结果为空时视为识别失败/动作失败。
- 固定坐标数组视同硬编码，仅特殊场景（如负坐标从边缘计算）使用并注明理由。
- `inverse: true` 反转识别后，Click 等点击自身的动作失效（实际没识别到东西）——此时有需求必须显式设置 `target`。
- OCR 的 `only_rec: true` 跳过文字检测、整个 `roi` 直接当一行识别，返回 box 也等于该 `roi`；Click 的落点取该 box 内的**随机点**（引擎 `Actuator::click` → `rand_point`：正态分布、中心附近概率最高），roi 越宽落点越可能偏离目标。**最坏是没填 `roi`**：`roi` 缺省 `[0,0,0,0]` 即全屏，此时 box = 全屏、落点在全屏范围内随机（仍中心偏置）；再叠加 `expected` 缺省匹配全部，一旦命中就会点到无关位置。
- `roi` 收紧到目标实际出现区域：提速且防误命中；支持负坐标与负尺寸（引入版本路由核对）。例外：走文字检测（非 `only_rec`）时，收紧后仍要留出文字四周的**切行余量**——检测靠边距切行，贴太紧会让识别文本缺字/带噪，这时该给 roi 留边，不要调阈值。（机制：det 没出框时引擎会把整块 roi 直接送 rec、box 也等于 roi——`OCRer` 的回退分支；所以「文本混入 + box=roi」不只 `only_rec` 会出现，det 失败同样会。）
- 去掉 `only_rec` 改用文字检测后，若 roi 内会出现多行文字：用 `expected` 锁文案、`order_by` 定顺序、`index` 取具体行（缺省 `expected` 匹配全部、`order_by: Horizontal`、`index: 0`），否则可能命中错行或任意文字。

## 反模式清单

| 反模式 | 后果 | 正确做法 |
| ------ | ---- | -------- |
| `DirectHit` + 硬编码 target | 界面变化即点错 | 识别节点 + box 继承 |
| 长 pre_delay/post_delay 凑等待 | 又慢又不稳 | 中间过程节点 + 等待目标出现 |
| `timeout: -1` 滥用 | 流程挂死 | 合理超时 + on_error 兜底 |
| 循环无 `max_hit` 限次 | 死循环死磕 | 出口节点 + max_hit |
| `$` 开头 root 字段当业务节点 | 整个节点不被解析 | 只用于注释/停用 |
| 同名节点依赖覆盖顺序 | 随加载顺序变化的隐性行为 | 重名视为错误，立即修复 |
| 节点改名不搜引用 | 后果按引用位置分四档（加载期报错 / 运行期失败 / 调用即失败不回滚 / 静默失联或漂移——见 [naming.md](naming.md) 引用核对表） | 改名前全库搜索 |
| 编造字段名/参数 | 加载报错或静默失效 | 路由 MaaLLMWiki 核对 |
| 点击没反应就盲目再点一次（无识别门控） | 第二次点击可能作用于下一界面的其他元素 | wait_freezes 等画面静止 / 重新识别按钮仍在才再点 |
| A 失败换 B、B 失败换 C 式重试 | 掩盖根因，问题无法定位 | 修根因；确需重试设计成有限次 |
| 死循环盲目加 max_hit | 识别/逻辑缺陷被硬中断，后果难预估 | 找根因修节点；max_hit 只作安全带 |
| 模板在本机能中、他人设备不中 | 跨设备捕获差异（模拟器 GPU 渲染、截图路径）、阈值卡太死 | 阈值留裕度（目标位实测 − 约 0.1 起步（经验值），且高于误配最高分——两侧贴太近是模板/roi 问题，调阈值救不了）；识别不稳时在该设备实测 |
| OCR 在框不精确的 roi 上开 `only_rec` | 整块 roi 被当一行识别（混入相邻文字/美术字）+ box 等于 roi、点击落点在该 roi 内随机 → 可能点在目标外 | **只有 roi 能精确框住目标那一行文字**（位置固定、框贴合、框内无其它文字）才保留 `only_rec`；否则去掉它、让检测给出真实文字框，并用 `expected` / `order_by` / `index` 锁目标行（细则见上文「坐标卫生细则」） |

## 审查清单

1. 坐标卫生：无 DirectHit+硬编码 target；target_offset 与特殊固定坐标有依据。
2. 流程：next 链画出来无不可达节点、无死路（每个 next 有 on_error 出口）；循环有限次。
3. 保留字用法：`$`/`.` 的使用是刻意的；`default_pipeline.json` 在资源包根。（`is_sub`/`interrupt` 无需审查项——`MaaFW v5.1+` 加载即报错并自带迁移脚本指引。）
4. anchor：三形式使用正确；每个被引用的锚点在所有前置路径上都被设置过。
5. 版本兼容：用到的字段的引入版本与语义，路由 MaaLLMWiki 的版本变更目录核对，确认项目基线支持。
6. OCR：`only_rec` 只出现在「roi 能精确框住一行文字」的节点上；去掉 `only_rec` 后按「坐标卫生细则」的检测余量条检查 roi（识别文本缺字/带噪 = roi 太贴，该调 roi 不是阈值）。
