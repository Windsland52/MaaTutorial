# 反模式清单与审查清单

配套 [SKILL.md](../SKILL.md) 的审查要点展开。判定依据：MaaLLMWiki 路由的 3.1-任务流水线协议（版本锁定）。文中括号内的版本标注仅作提示，实际支持范围以路由结果为准。

## 坐标卫生细则

协议区分三个概念：`roi`（在哪识别）、`box`（识别命中返回的区域）、`target`（动作执行目标，默认 `true` 即继承当前识别 box，动作目标由 `target` + `target_offset` 共同决定）。

- **严禁 `DirectHit` + 硬编码 target**：绕过识别直接点绝对坐标，界面一变就点错。
- 点击目标默认继承本节点识别 box；OCR/Template 节点直接让点击落在识别结果上，需要偏移用 `target_offset` 并注明依据。
- 锚定偏移（引用之前执行过的节点的 box，string 形式写节点名，或 `[Anchor]锚点名` 引用）只在“目标相对参照物位置恒定”时可用，并注释前提；引用的节点/锚点识别结果为空时视为识别失败/动作失败。
- `inverse: true` 反转识别后，Click 等点击自身的动作失效（实际没识别到东西）——此时有需求必须显式设置 `target`。
- `roi` 收紧到目标实际出现区域：提速且防误命中；支持负坐标与负尺寸（引入版本路由核对）。

## 反模式清单

| 反模式 | 后果 | 正确做法 |
| ------ | ---- | -------- |
| `DirectHit` + 硬编码 target | 界面变化即点错 | 识别节点 + box 继承 |
| 长 pre_delay/post_delay 凑等待 | 又慢又不稳 | 中间过程节点 + 等待目标出现 |
| `timeout: -1` 滥用 | 流程挂死 | 合理超时 + on_error 兜底 |
| 循环无 `max_hit` 限次 | 死循环死磕 | 出口节点 + max_hit |
| `$` 开头 root 字段当业务节点 | 整个节点不被解析 | 只用于注释/停用 |
| 同名节点依赖覆盖顺序 | 随加载顺序变化的隐性行为 | 重名视为错误，立即修复 |
| 节点改名不搜引用 | next/anchor/override/run_task 静默失联 | 改名前全库搜索 |
| 编造字段名/参数 | 加载报错或静默失效 | 路由 MaaLLMWiki 核对 |
| 点击没反应就盲目再点一次（无识别门控） | 第二次点击可能作用于下一界面的其他元素 | wait_freezes 等画面静止 / 重新识别按钮仍在才再点 |
| A 失败换 B、B 失败换 C 式重试 | 掩盖根因，问题无法定位 | 修根因；确需重试设计成有限次 |
| 死循环盲目加 max_hit | 识别/逻辑缺陷被硬中断，后果难预估 | 找根因修节点；max_hit 只作安全带 |
| 模板在本机能中、他人设备不中 | 跨设备捕获差异（模拟器 GPU 渲染、截图路径）、阈值卡太死 | 阈值留裕度（目标位实测 − 约 0.1 起步，且高于误配最高分）；识别不稳时在该设备实测 |

## 审查清单

1. 坐标卫生：无 DirectHit+硬编码 target；target_offset 有依据。
2. 流程：next 链画出来无不可达节点、无死路（每个 next 有 on_error 出口）；循环有限次。
3. 保留字用法：`$`/`.` 的使用是刻意的；`default_pipeline.json` 在资源包根。（`is_sub`/`interrupt` 无需审查项——v5.1+ 加载即报错并自带迁移脚本指引。）
4. anchor：三形式使用正确；每个被引用的锚点在所有前置路径上都被设置过。
5. 版本兼容：用到的字段的引入版本与语义，路由 MaaLLMWiki 的版本变更目录核对，确认项目基线支持。
