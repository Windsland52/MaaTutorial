# Agent 子进程模式与工程规范

配套 [SKILL.md](../SKILL.md) 工作流第 1 步（定宿主与注册路径）。interface.json 的 `agent` 段三字段：`child_exec`（必填）、`child_args`、`identifier`，子进程 CWD = interface.json 所在目录——细节路由 3.3 原文。架构事实以 MaaLLMWiki 路由的协议原文为准。

## 架构与职责分层

```text
主程序（通用 GUI / 自研 Client）
   │  按 interface.json agent 段拉起子进程，注入 PI_* 环境变量
   ▼
agent 子进程：启动 → 环境 → 注册 → 连接 → 待命运行 → 退出
```

各阶段职责（语言中立，实现形态随 binding 惯用法）：

- **启动（薄入口）**：只做进程级防护与初始化——崩溃防护与日志落地、输出流编码兜底、平台差异隔离（用该语言惯用机制）、运行模式分发、**取连接标识符**（见下），然后委托下层；入口里不写业务。
- **环境**：把子进程运行环境的不确定性（agent 模式最大故障源）变成可复现的确定性步骤。工作量随语言伸缩——解释型语言要管运行时版本、虚拟环境与依赖锁定（binding 版本与主程序加载的 MaaFW 兼容）；编译型语言大多在编译期完成，只剩运行期库定位。
- **注册 → 连接 → 待命**：实现全部注册**之后**才建立与主程序的连接、进入待命；此后回调驱动执行。唯一硬约束是**注册早于连接**（注册时机本身是项目约定——就近声明随模块加载生效，集中注册由入口显式调用）。
- **退出**：AgentServer 是单线程消息循环、回调串行执行——停止请求只在当前回调返回后才被派发，天然"跑完手头再退"；但**框架引擎不认识子进程**，Tasker / Resource / Controller 的停止与销毁既不等待也不杀它——收尾由 Client 显式断开连接完成，主程序侧对 agent 退出要有可见提示。

连接标识符：Client 把自动生成的标识符**追加为子进程最后一个命令行参数**，入口取它连接（协议未明载此约定，官方示例取最后一个 argv；参考实现的 `identifier` 字段解析后未使用——要固定标识符只能自研 Client）。

agent 能力面 = **Context API + 远端代理**：控制器 / Tasker / Resource 的创建与插件加载在 agent 子进程内均不可用（框架侧显式未实现、直接返回空）——非标设备控制等须由 Client 侧提供。

## PI_* 环境变量容错

- 变量集合做成常量表统一枚举，逐项读取；**任何变量可能缺省或为空**（协议允许 Client 不设置），读不到就走默认而不是崩。
- `PI_CONTROLLER` / `PI_RESOURCE` 是单行紧凑 JSON，其中**顶层 label / description 已解析为展示文本**（非递归——嵌套对象里的 `$` 不展开），解析失败按缺省处理并记日志。
- 这些变量只反映启动时刻的选择；运行期切换是否重启子进程由 Client 决定，custom 不要假设能感知切换。
- 实现是把变量写进 **Client 自身进程环境**、子进程只是继承——同批拉起的 pretask / `Command` 子进程也会带上 `PI_*`，它不构成"agent 专属环境"的判据。

## 双日志纪律

- 主程序日志与 agent 日志是**两路**：起不来先看 agent 自己的输出——启动各阶段（环境、依赖、注册、连接）都落日志，阶段边界清晰。
- 子进程崩溃不会自动重启：注册完成、连接成功这类里程碑事件单独打日志。
- Windows 控制台编码是经典坑：入口处显式设置输出流编码（UTF-8）；输出重定向的平台差异用该语言惯用的隔离机制处理，不在业务代码里堆平台分支。

## 生命周期与状态

- 注册完成 → 连接建立 → 待命，三个阶段依次确认（注册早于连接，见上）。
- agent 进程存活期 = 实现侧状态存活期（见 SKILL.md 硬护栏 5 与 patterns.md「状态与作用域」）；不要缓存"上次任务"的设备 / UI 状态，每次以任务入参为准。

## 进程内还是子进程：先看宿主，再看隔离需求

- **宿主决定可选项**：随资源分发给通用 GUI/Client → Agent 子进程是官方推荐且最常用的注册路径（Client 按 interface.json `agent` 段拉起子进程并连接）；自研 Client 或宿主提供插件接口 → 才有进程内注册的选项（宿主侧资源注册接口，即文档所谓"通过 UI 注册"；原生插件当前只暴露事件回调 ABI、无 custom 注册入口，不作为发布方案）。另：框架进程不会自动加载资源包里的代码，但资源分发可以带脚本、由 Client 以子进程执行（agent 段、pretask、`Command` 动作）。
- 自研场景再按隔离需求选：**语言隔离**（主程序不带目标语言运行时）、**重逻辑隔离**（崩溃不连坐、可独立重启）——两个都没有就进程内直接注册，别引入双进程的排障成本。
